# SleepThrough Android — 0.4.0 pilot

Новый интерфейс в духе RISE и путь уроков с элементами Duolingo; общий отчёт по данным Samsung Health и дневника. Правила объединения и проверка: [DESIGN_AND_REPORTS.md](DESIGN_AND_REPORTS.md).

Устанавливаемый Android-проект на Capacitor 8.6.0 с собственными Kotlin-модулями Health Connect и Android Keystore. Локальный профиль позволяет пользоваться дневником, уроками и импортом без регистрации. Демо-данные в личный профиль не подставляются.

В 0.4.0 добавлены обработка вложенных ошибок Android Keystore, системная задержка повторов и проверка чтения новой записи до коммита. Сохранена защита 0.3.1: после ошибки чтения приложение блокирует запись, чтобы не заменить прежние данные пустым состоянием. Фактический сбой пользователя на 0.3.1 ещё не воспроизведён: новый экран показывает этап, класс причины и модель Android для диагностики. Формат шифрования и alias ключа сохранены. Подробности и пределы проверки: [CHANGELOG.md](CHANGELOG.md).

## Что реализовано

- Мобильный кабинет, нижняя навигация, выбор источника, дневник и аналитика 7/28 дней.
- 16 вопросов с пропуском, несколькими вариантами в соответствующих вопросах, объяснимым результатом и историей assessment-записей.
- 28 локальных уроков, три шага, рефлексия, прогресс и баллы за уникальное завершение.
- Текстовый ночной протокол без сети и без входа.
- Нативный Health Connect: READ_SLEEP, проверка доступности/доступа, импорт со всеми страницами, Samsung dataOrigin, Changes API, обновления/удаления, восстановление курсора, выбор сессий, источник и полнота данных.
- Раздельное хранение дневника и Samsung. Неизвестное значение не превращается в ноль. Расчёт из стадий исключает начальное и финальное бодрствование.
- AES-GCM-хранилище с ключом Android Keystore; резервное копирование приватных файлов отключено. Android-токены не сохраняются в обычном localStorage.
- Supabase email/password, PKCE и callback `sleepthrough://auth/callback`; нормализованные записи с RLS, revision и разрешением конфликтов; явный перенос локальных записей.
- Health cloud sync — отдельный выбор, off по умолчанию. Сырые стадии не загружаются.
- JSON/CSV-экспорт через системный выбор получателя, удаление локальных копий; серверная функция удаления своего аккаунта с повторной проверкой пароля.

## Проверено и что ещё проверить

**Выполнено для 0.4.0:** сборка debug APK, Android lint без ошибок (15 предупреждений), 27 автоматических JS-теста. На эмуляторе Android 16/API 36: реальный WebView → Kotlin → Android Keystore round trip; Activity recreation; отдельные процессы записи/чтения; повреждённый шифротекст не заменяется; обновление поверх APK 0.3.1 сохраняет профиль, дневник, урок и ответы квиза. Проверены точный этап ошибки Preferences и классификация вложенного криптографического отказа без приватного сообщения. Подписи APK совпадают, versionCode повышен с 2 до 4.

**Ранее выполнено для 0.3.0:** транзакционный RLS-тест двух UUID на живой базе; неавторизованный запрос удаления получает 401. В браузерном preview проверены локальный профиль, пустой кабинет, чек-ин, аналитика, урок/рефлексия/очки, 16 пропусков квиза и ночной протокол. Эти серверные проверки в 0.4.0 повторно не запускались: сервер не менялся.

**Не выполнено на физическом Android:** Samsung-импорт реальных ночей, системный отказ/отзыв, Keystore при перезапуске конкретного телефона, клавиатура/Back/TalkBack, измерение производительности, email callback. Подключённого физического телефона нет. Сообщённая пользователем ошибка повторного входа на эмуляторе не воспроизвелась; её точная причина на телефоне пока не установлена. Новая сборка показывает безопасный support code без содержимого записей или токенов.

SMTP проекта пока не подключён. Письма внешним пользователям могут быть недоступны; полный регистрационный/reset-сценарий не проверен. Для использования сейчас предназначен локальный профиль. При включении SMTP пройти сценарий подтверждения/восстановления на реальном email.

Это пилотная debug-сборка, не принятый production-релиз и не публикация Google Play. Экспертная редактура контента и весь физический чек-лист ТЗ остаются условиями публичного выпуска. P1-уведомлений, русского перевода и медиатеки нет.

Очистка устаревших локальных стадий/сводок выполняется при открытии и возврате в приложение, даже если импорт приостановлен. Очистка устаревших облачных сводок выполняется при следующей синхронизации аккаунта; отдельное серверное TTL-задание для неактивных аккаунтов не подключено.

Текущий веб-сайт продолжает использовать прежнее JSON-хранилище. Android однократно переносит старые данные аккаунта в новую модель; постоянная двусторонняя синхронизация со старым веб-интерфейсом не реализована. Между Android-установками используется новая модель записей.

## Сборка

Требуются Node 24, pnpm, JDK 21, Android SDK platform 36 и build tools; Gradle wrapper — 8.14.3, AGP — 8.13.0. В SDK должны быть необходимые лицензии. Настройте `JAVA_HOME`, `ANDROID_HOME` и `android/local.properties` под свой компьютер; этот файл не коммитится.

```sh
cd mobile
pnpm install --frozen-lockfile
pnpm test
pnpm run sync
cd android
./gradlew :app:assembleDebug :app:lintDebug
```

В Windows последняя команда — `./gradlew.bat :app:assembleDebug :app:lintDebug`.

APK: `android/app/build/outputs/apk/debug/app-debug.apk`. Debug-подпись создаётся локальным Android toolchain. Не удаляйте пользовательский debug keystore, если нужны совместимые обновления этого пилота; для релиза владелец должен отдельно настроить собственную подпись. Ключи и пароли не входят в архив исходников.

Для существующей установки используйте готовый APK 0.4.0 с прежней подписью и устанавливайте поверх приложения. Не удаляйте его и не очищайте данные для устранения ошибки хранилища. Самостоятельная сборка на другом компьютере создаст другой debug-ключ и не заменит установленный APK.

Нативные регрессионные тесты собираются командой `./gradlew :app:assembleDebugAndroidTest`. Запускайте `VaultReopenTest` через AndroidJUnitRunner; четыре fixture-метода по умолчанию пропускаются и требуют явного аргумента `fixture`. `seed-upgrade` разрешён только на отдельном тестовом эмуляторе: он создаёт синтетический локальный профиль для проверки обновления. Порядок и команды приведены в [CHANGELOG.md](CHANGELOG.md).

Стабильный пакет: `com.sleepthrough.app`; min API 28, target API 36. Поддержка Health Connect проверяется во время выполнения; Google Play services/провайдер и источник Samsung должны быть доступны.

## Серверная часть

- Схема: `../database/mobile-schema.sql`, уже применена к отдельному SleepThrough Supabase-проекту.
- Таблица `sleepthrough_mobile_records`: один профиль/дневник/урок/assessment/health summary на отдельный ID; RLS по `auth.uid()`.
- `../supabase/functions/sleepthrough-delete-account/index.ts` развёрнута. Gateway verify_jwt выключен для совместимости ключей, но функция сама обязательно проверяет bearer через Supabase `getUser()`; требуется свежий password AMR. ID пользователя берётся только из проверенного токена.
- Publishable key и URL копируются из `../dist/config.js`. Это публичная конфигурация; service-role доступен только внутри managed Edge runtime, не в APK.
- Callback добавлен в allowlist Supabase. Для восстановления PKCE-письмо должно открываться на той же установке, где запросили reset; verifier хранится защищённо.

## Структура

`src/main.js` — экраны и события; `src/store.js` — secure storage, синхронизация, импорт; `src/sleep.js` — вычисления; `src/quiz.js` — вопросы и правила; `src/export.js` — CSV. `android/app/src/main/java/com/sleepthrough/app` — нативные модули. `www` генерируется и не является исходником.

`node preview.cjs` запускает browser preview на 127.0.0.1:3188 после `pnpm run build`. В preview нет нативных данных, а записи временные и сбрасываются при reload. Нативные возможности проверяются в APK.
