# Stripe Sandbox — веб-интеграция

6 ноября 2026. Опубликовано: https://sleepthrough-production.up.railway.app . Исходники: https://github.com/Levinate/sleepthrough . Локальная версия также поддерживается.

## Реализовано

- Настоящий Stripe-hosted Checkout в sandbox. В коде принимаются только секретные ключи `sk_test_…`; ответы Stripe с `livemode: true` отклоняются.
- Три подписки: $16.99 → $29.99 каждый месяц, $27.99 → $49.99 каждые 3 месяца, $39.99 → $69.99 каждые 6 месяцев.
- Базовая recurring price соответствует продлению. Однократный купон снижает только первый счёт на $13 / $22 / $30 соответственно. Цена проверяется сервером, клиент не задаёт сумму.
- Checkout на английском, USD; Adaptive Pricing отключён в создаваемой Session.
- Согласие перед checkout, защита повторного создания через idempotency key.
- Возврат после оплаты: сервер заново читает Session в Stripe и проверяет sandbox, владельца браузера, статус `complete`, оплату `paid`, валюту и итоговую сумму. Одного параметра успешного URL недостаточно для открытия онбординга.
- Отмена продления в два нажатия: `cancel_at_period_end=true`; доступ остаётся до конца оплаченного тестового периода.
- Пауза сбора тестовых платежей на календарный месяц: `pause_collection.behavior=void`, `resumes_at`. Она не отключает доступ и не продлевает автоматически текущий расчётный период; интерфейс это указывает.
- Секрет хранится только в серверном окружении / игнорируемом `.env.local`. Публичный ключ для Stripe-hosted формы приложению не нужен. Номер карты вводится только на Stripe.

## Как запустить

1. Для нового локального checkout: `node scripts/prepare-stripe-local.cjs` создаст `.env.local`, если файла ещё нет, и случайный секрет подписи cookie. Содержимое и ключи не печатаются.
2. Вставить sandbox Secret key в строку `STRIPE_SECRET_KEY=`. `STRIPE_COOKIE_SECRET` сохранять между перезапусками.
3. `node build-web-mvp.mjs`, затем `node server.cjs`. `SITE_URL` должен точно соответствовать адресу сайта; для текущей версии это `http://127.0.0.1:3191`.
4. Тестовая карта Stripe: `4242 4242 4242 4242`, любая будущая дата и тестовый CVC. Реальные карты для тестирования не использовать.
5. Пройти план → согласие → Stripe Checkout → онбординг. Управление тестовой подпиской — в My account, из того же браузера.

## Проверка

Ключ принят Stripe с `livemode=false`. В изолированном локальном профиле на порту 3194 прошли реальный sandbox Checkout на $27.99, серверная проверка возврата, онбординг, месячная пауза, отмена в конце периода и повторная проверка после перезагрузки. Продление $49.99 / 3 месяца видно в Stripe. Реальные деньги не перемещались.

11 автоматических проверок: запрет live-ключей и live-ответов, три цены и однократные скидки, обязательное согласие/Origin, идемпотентность, владение checkout, запрет доступа по неоплаченному Session, отмена/пауза, блокировка неправильной суммы/валюты и выбор email для вошедшего пользователя. Проверки авторизации, уроков и HTTP также прошли.

На публичном Railway проверены health, включённый test-only API, наличие исправленного поля email и создание месячного Stripe Checkout. Сессия создана без проведения платежа. Секретные файлы по HTTP возвращают 404.

Проверено отсутствие секретного ключа в 39 публичных файлах веба и собранного Android-интерфейса. `.env.local` и серверный модуль возвращают HTTP 404 при запросе через сайт.

## Границы пилота

Это test-only интеграция для демо, не приём реальных платежей. Управление до регистрации привязано к подписанной HttpOnly-cookie браузера, в котором был checkout; Supabase-аккаунт пока не является платёжным владельцем между разными устройствами. Для платного продакшена понадобятся отдельная связь subscription/customer с проверенным аккаунтом, webhook-обработка жизненного цикла и серверные права доступа. Текущая версия не использует Stripe-события для ограничения доступа к учебным материалам.

Сервер Node.js реализует `/api/payments/*`; старый статический Railway Function bundle эти маршруты не обслуживает. На Railway используется Docker/Node-сервис с серверными переменными окружения. Ключи не включать в `dist`, APK или архив исходников.

Существующий APK 0.5.0 сохраняет демонстрационную оплату; Stripe Sandbox подключён в вебе. Подключение Android к серверной оплате — отдельная работа.

Основные файлы: `payments/stripe.cjs`, `server.cjs`, `web-src/mvp-web.js`, `check-payments.test.cjs`.
