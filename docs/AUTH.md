# Авторизация SleepThrough

## Что подключено

- Supabase project `rngkrplxjdlzizhwdhog`, NOA, eu-central-1.
- Email/password: регистрация, вход, подтверждение почты, восстановление пароля, выход.
- Личный профиль, дневник ночей, рефлексии и прогресс уроков.
- RLS: каждая строка принадлежит `auth.uid()`, пользователь не видит чужую строку.
- Публичный ключ в `dist/config.js`. Service role не нужен.
- Site URL: `https://sleepthrough-production.up.railway.app`.
- Redirect allowlist: `https://sleepthrough-production.up.railway.app/**`.

## Что завершить владельцу

В [SMTP Settings](https://supabase.com/dashboard/project/rngkrplxjdlzizhwdhog/auth/smtp) подключить свой почтовый сервис. Нужны host, port, username, SMTP password и подтверждённый адрес отправителя. Пароль следует вводить прямо в Supabase, не в GitHub, код или чат.

Подтверждение email остаётся включённым. Без своего SMTP встроенный отправитель ограничен адресами команды организации. Формы и API подключены, но массовая регистрация ещё не готова.

После настройки проверить своим тестовым адресом:

1. Регистрация → письмо → подтверждение → Sign in.
2. Новый кабинет пустой, урок начинается с дня 1.
3. Сохранить чек-ин и рефлексию, завершить урок, обновить страницу.
4. Войти с другого браузера — записи должны загрузиться.
5. Второй аккаунт не видит эти записи.
6. Forgot password → письмо → новый пароль → повторный вход.

[Документация Supabase SMTP](https://supabase.com/docs/guides/auth/auth-smtp).

## Локальный запуск

`node server.cjs`. Вход существующего аккаунта может работать локально; письма возвращают на production по Site URL. Для локальной проверки callback нужно явно добавить локальный origin в allowlist, затем убрать после проверки.

## Данные и ошибки

Таблица: `public.sleepthrough_user_state`. Snapshot схемы — `database/schema.sql`; в существующем проекте повторно его не выполнять. Для нового окружения создайте Supabase-проект, выполните схему, замените URL и publishable key, настройте Site URL, redirects и SMTP.

Неуспешное сохранение показывает Retry. Ошибка чтения блокирует редактирование. Выход ожидает завершения сохранений. При работе двух устройств используется последняя записанная версия: автоматического объединения изменений пока нет.

## Верификация

`node check-auth.cjs` проверяет SDK-модель: подтверждение почты, reset, пустой аккаунт, нормализацию, сбой/повтор записи, безопасный выход, изоляцию аккаунтов и запрет перезаписи после ошибки загрузки.

На живой базе проверены политики и транзакционная изоляция временных UUID (без настоящих email/паролей, с rollback). Security Advisor вернул пустой список. Это не заменяет полный сценарий письма после подключения SMTP.
