# Запуск и публикация

## Локальная разработка

```bash
node server.cjs
```

Адрес: http://127.0.0.1:3000. Зависимости устанавливать не нужно. Для изменения порта задайте `PORT`, а для прослушивания контейнерной сети — `HOST=0.0.0.0`.

PowerShell:

```powershell
$env:PORT = '8080'
$env:HOST = '0.0.0.0'
node server.cjs
```

Сервер не имеет hot reload: после изменения файлов обновляйте страницу вручную.

## Текущий Railway Function

- Сайт: https://sleepthrough-production.up.railway.app
- Проект: SleepThrough.
- Сервис: sleepthrough, окружение production.
- Runtime опубликованной версии: Bun 1.4.4.
- Публичный домен направлен на порт 8080; код читает переменную `PORT`.
- Код не зависит от локальной файловой системы после генерации.

Для подготовки обновлённого исходника:

```bash
node scripts/build-railway.cjs
```

Результат — `build/railway-function.ts`. Генератор проверяет размер файла (лимит Railway Functions — 96 KB) и ответы встроенного обработчика. Файл нужно отдельно передать в существующий сервис через Source Code в Railway или соответствующий инструмент обновления функции. Генератор не выполняет загрузку и не содержит токенов.

Не редактируйте закодированные данные внутри сгенерированного файла. Меняйте `dist`, затем генерируйте исходник заново. Директория `build` исключена из Git.

## Деплой репозитория как Docker-сервиса

В репозитории подготовлены `Dockerfile` и `railway.json`. Это стандартный вариант для последующего автоматического деплоя по Git push.

1. В Railway выберите нужный проект и создайте отдельный сервис из GitHub-репозитория `Levinate/sleepthrough`.
2. Предоставьте Railway доступ к приватному репозиторию, если он его запросит.
3. Используйте корень репозитория. Railway должен собрать приложенный Dockerfile.
4. Контейнер запускает `node server.cjs`, слушает `0.0.0.0` и использует `PORT`.
5. Дождитесь успешного healthcheck `/health`.
6. Сгенерируйте домен для нового сервиса и проверьте страницы, стили и переходы.
7. Подключайте основной домен после проверки нового сервиса.

**Эти действия ещё не выполнены:** в GitHub загружается исходный проект и конфигурация, а действующая Railway Function продолжает работать своим способом. Само наличие `railway.json` не подключает GitHub к существующей Function.

Параметры в `railway.json`: Dockerfile builder, healthcheck `/health`, таймаут 30 секунд и перезапуск при ошибке с тремя повторными попытками. Секреты для этого статического прототипа не нужны.

## Проверка Docker локально

При установленном Docker:

```bash
docker build -t sleepthrough .
docker run --rm -p 8080:8080 sleepthrough
```

Откройте http://127.0.0.1:8080. Docker-конфигурация подготовлена; факт её присутствия не означает, что образ уже опубликован в реестре.

## Кеш и данные

Версии CSS и JS задаются query-параметрами в `index.html`. При изменении интерфейса обновляйте их, особенно если используете старый Function-обработчик с кратковременным кешированием ассетов.

Демоданные браузера не переносятся между доменами. Данные аккаунта хранятся в Supabase и загружаются после входа. Supabase URL и publishable key находятся в `dist/config.js`; секретных ключей в интерфейсе нет. Подключение SMTP и настройки возврата после писем описаны в [AUTH.md](AUTH.md). В версии лендинга V5 обе WebP-фотографии и новые landing.js/landing.css включены в Function. Таблица ресурсов сжата Brotli; генератор проверяет полный лимит 96 KB. SDK загружается отдельно с закреплённой версией и SRI.
